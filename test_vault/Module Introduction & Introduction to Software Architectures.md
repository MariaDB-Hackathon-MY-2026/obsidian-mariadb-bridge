
**1. Definition of Software Architecture*

- **Core idea:**  
    → The _fundamental organization of a system
    
- Includes:
    
    - Components
        
    - Relationships between components
        
    - Interaction with environment
        
    - Design & evolution principles
        

Alternative phrasing:

- Structure of system + elements + relationships + externally visible properties
    

 **2. Key Concepts / Terms (Must Use Correctly)**

- Software architecture
    
- Dependencies
    
- Human motivation
    
- Longevity
    
- Social structure
    

---

 **3. Types of Architecture**

- Enterprise Architecture
    
- Network Architecture
    
- Hardware Architecture
    
- Software Architecture
    

---

# **4. Software vs Computer Architecture**

- **Computer architecture:** hardware-focused (rules, organization, implementation)
    
- **Software architecture:** system structure & design of software systems
    

---

# **5. Simple vs Complex Systems**

### Small systems (e.g., bookstore system)

- Fewer people
    
- Simple tools
    
- Basic models
    

### Large systems (e.g., Grab, AirAsia, Microsoft 365)

- Expert teams
    
- High cost
    
- Advanced models & technologies
    
- Structured processes
    

---

# **6. Drivers of Software Architecture**

Architecture decisions are based on:

- Quality attributes (performance, security, etc.)
    
- Requirements / scenarios
    
- Risks
    
- Cost
    
- Time
    
- Users
    

---

#  **7. Why Software Architecture is Needed**

- Controls IT infrastructure
    
- Maintains system integrity
    
- Aligns stakeholders/goals
    
- Enables scalability
    
- Improves maintenance
    
- Enhances security
    
- Reduces recovery cost
    

---

#  **8. Goals of Software Architecture**

- Provide a **framework** for system development
    
- Align IT with business goals
    
- Organize requirements early
    
- Optimize time, cost, and resources
    
- Support system evolution
    

⚠️ Important:

- Architecture ≠ final product
    
- It’s the _foundation/structure_
    

---

# **9. People Involved**

- System Architect (lead role)
    
- Engineers (network, security, etc.)
    
- Analysts / Consultants
    
- QA team
    
- Risk & legal team
    
- End users
    

---

#  **10. Architecture in SDLC**

- Created during **design phase**
    
- Guides:
    
    - Development
        
    - Testing
        
    - Implementation
        

---

#  **11. Consequences of No Architecture**

- No clear direction
    
- Poor scalability
    
- Security vulnerabilities
    
- System incompatibility
    
- Failures in services
    
- High maintenance/recovery cost
    
- Business growth failure
    

---

#  **12. Architecture as a Blueprint**

Architecture supports:

- Team structure
    
- Documentation
    
- Work breakdown
    
- Scheduling & budgeting
    
- System communication & coordination
    


 **13. Why It Matters (Exam Summary Statement)**

Software architecture:

- Provides **technical foundation**
    
- Creates **sustainable competitive advantage**
    
- Ensures system works as intended
